# 网上评卷系统完整实现路径与计划

本文是 `grading` 应用从当前 MVP 走向可生产运行的实施路线。目标是形成“扫描接入 → 图像识别 → 脱敏切块 → 智能分发 → 双评仲裁 → 质检复核 → 成绩发布”的可审计闭环。

## 当前基线

已完成：

- Django `grading` 领域应用、考试/题目/批次/答题卡/任务/审计模型。
- Django 原生“教师”组与 `grade_answers` 权限。
- 任务领取、提交、超时回收及事务锁。
- 双评分发、分差阈值和管理员仲裁。
- Pillow 基础图像质量识别：EXIF 方向、分辨率、墨迹比例、内容区域。
- React 教师评卷工作台。
- Vite 生产构建已验证通过。

当前识别器是可替换的基础实现，不能替代正式 OCR/OMR 引擎；扫描批次处理目前仍可同步执行。

## 阶段 3：扫描流水线与 OCR/OMR

### 目标

把原始扫描文件转成结构化答题卡、考号和题块图像，并支持失败重试与人工复核。

### 实施顺序

1. **文件拆包与页级模型**
   - 增加 `ScanPage`：页码、原图、旋转角度、裁剪框、质量状态。
   - 支持 PDF、TIFF、多页 TIFF、ZIP 图片和普通图片。
   - 对原始文件计算 SHA-256，避免重复导入。
2. **版面定位**
   - 使用 OpenCV 检测定位点、边框和答题卡模板。
   - 建立 `ExamTemplate` 和模板版本，保存定位点与题块坐标。
   - 透视变换、去黑边、去噪、二值化和统一 DPI。
3. **OCR**
   - 考号 OCR 结果保存原始文本、标准化文本、置信度和候选值。
   - 低置信度进入人工确认队列。
   - 记录 OCR 引擎、模型版本和请求耗时，保证可追溯。
4. **OMR**
   - 客观题保存每个选项的像素值、选择结果和置信度。
   - 多选题、漏涂、擦除和冲突结果进入复核。
   - 客观题答案与试卷答案版本绑定，禁止直接覆盖历史结果。
5. **异步任务**
   - 上传完成后写入 `RecognitionJob`，由 RQ Worker 执行。
   - 任务状态：`queued → processing → completed/failed`。
   - 指数退避重试，超过次数进入人工处理队列。

### 验收标准

- 单批次可重复处理且不产生重复答题卡。
- 识别失败可定位到具体页和具体原因。
- OCR/OMR 结果有置信度和人工复核入口。
- 原图、处理图、题块图均可通过权限校验访问。

## 阶段 4：题块分发与教师工作台增强

### 目标

将“整张答题卡”升级为教师只可见的脱敏题块，并根据教师权限、负载和质量动态分配。

### 实施顺序

1. 增加 `AnswerBlock`：题目、图像文件、坐标、脱敏状态和质量状态。
2. `GradingAssignment` 改为绑定 `AnswerBlock`，教师不直接接触考号和原始答题卡。
3. 建立教师能力配置：
   - 科目权限
   - 题目权限
   - 年级/区域范围
   - 最大并发任务数
4. 分发算法：
   - 轮询作为默认策略。
   - 按教师当前未完成数进行负载均衡。
   - 同一考生同一题的双评禁止分配给同一教师。
5. 工作台增强：
   - 题块缩放、旋转、灰度和适配宽度。
   - 评分细则面板。
   - 键盘快捷键和自动保存草稿。
   - 断线重连、任务锁续租和浏览进度。

### 验收标准

- 教师无法通过接口获得考生身份和其他题块。
- 双评任务的两个教师不重复。
- 任务锁可续租，浏览器关闭后可安全回收。
- 工作台支持图片加载失败重试和人工标记异常。

## 阶段 5：双评仲裁与质量控制

### 目标

让评分差异、抽查、复核和仲裁形成独立流程，不直接修改原始评卷记录。

### 实施顺序

1. 双评规则按题目配置：
   - 绝对分差阈值
   - 百分比分差阈值
   - 是否允许第三评
2. 仲裁案件保存：
   - 两次或多次原始评分
   - 分差计算结果
   - 仲裁人、最终分、理由和时间
3. 质检抽样：
   - 按教师、题目、批次和异常分数抽样。
   - 质检结果不覆盖原始分，单独记录通过/驳回。
4. 教师质量指标：
   - 平均评卷时长
   - 与仲裁结果的偏差
   - 抽查通过率
   - 任务退回率
5. 成绩锁定：
   - 评卷完成后生成成绩快照。
   - 发布前必须通过复核和审批。

### 验收标准

- 原始评分不可变，所有调整有审计记录。
- 仲裁关闭后答题卡自动重新汇总。
- 成绩发布后禁止普通管理员直接修改。

## 阶段 6：生产化、监控和灾备

### 目标

满足大规模考试的稳定性、安全性和可恢复性要求。

### 实施顺序

1. PostgreSQL 分区或按考试归档，Redis 用于锁和队列。
2. 对象存储保存原始图、处理图和题块图，开启版本控制。
3. Nginx/Daphne/RQ Worker 水平扩展。
4. 监控：
   - 批次处理耗时
   - 队列积压
   - OCR/OMR 低置信度率
   - 任务领取和提交延迟
   - 仲裁率和异常分数率
5. 审计与安全：
   - 登录、权限变更、任务分配、评分、仲裁、发布全部留痕。
   - 原始答卷访问签名化、短时效、可撤销。
   - 管理员和仲裁权限启用二次确认。
6. 灾备：
   - PostgreSQL 增量/WAL 备份。
   - 对象存储跨区域备份。
   - 定期恢复演练。

2. RQ 版扫描任务执行器与任务重试。
3. OpenCV 模板定位和题块切割适配器。
4. OCR/OMR 引擎接口及低置信度复核 API。
5. 教师题块脱敏访问接口。
6. 工作台缩放、快捷键、草稿和自动续租。
7. 双评规则配置、第三评和质量抽查。

每一项都应同时补充：模型迁移、服务层测试、接口权限测试、失败场景测试和前端验收用例。

## 当前连续交付进度

在阶段 3 基础上，已继续落地以下阶段 4-6 的后端骨架：

- `TeacherProfile`：教师科目、题号范围、任务上限和启用状态。
- `GradingAssignment`：题块绑定、草稿分数、草稿评语和任务租约续期。
- `QualityReview`：已提交评分抽样质检和通过/驳回处理。
- `ScoreSnapshot`：成绩快照、锁定和发布状态。
- `ReleaseApproval`：成绩发布申请、审批、发布和考试关闭。
- 新增草稿、租约、质检、快照和发布 API。

这些接口已经形成可测试的业务闭环；正式生产上线前仍应接入真实 OCR/OMR、模板定位模型、对象存储签名下载、权限管理页面和监控告警系统。
